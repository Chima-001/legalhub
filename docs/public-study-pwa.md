# The LegalHub offline boundary

**A PWA is the existing website with an install experience and selected offline behavior.** `public/manifest.webmanifest` supplies LegalHub’s name, LH icons, Home start URL, theme and standalone window. `public/sw.js` is the service worker that supplies the offline study guides; it is not a second app. Installing is optional. A bookmark also works in a supported browser once the public pack is ready.

## What a student can do

1. Visit **Home → Offline study guides** or open `study/` while connected. No account is required for the guides. Wait for **Public guides ready on this device**; this means the worker is active and the public pack is available, not that a student has been verified or that mail works.
2. Use **Install LegalHub** if the browser offers it. If it does not, use its install/add-to-home-screen menu where supported (on iOS: Safari → Share → Add to Home Screen). The site still works as a website if the browser does not offer installation.
3. Disconnect. Relaunching the app at ordinary Home shows an offline page with **Open public study guides**. A saved link to `study/` opens the guide directly. Read the case-briefing, problem-question and source-checking chapters, including their exercises. These are public authored study methods, not current case-law data, uploaded materials or personal notes.

| Works offline after preparation | Needs a connection |
| --- | --- |
| The guide, chapter links, expandable examples, layout and LH icons. The installed Home launch shows a public fallback; **not** a snapshot of a signed-in dashboard. | Sign-in, confirmation/recovery links, signup, profile/level updates, private Library, PDFs and signed R2 links, real semester desks, term countdown, current catalogue, searches of the live Library, uploads, moderation, admin/owner tools and admin email. |

A first visit with no internet cannot prepare an app. Browser eviction, private browsing, blocked workers or cleared site storage can require another online visit. Offline navigation straight to a private page can show the browser’s offline error rather than a guide. An already-open screen or a PDF a person explicitly downloaded through their browser is not erased by this worker; that is separate from the PWA store. No posts, uploads, profile edits, approvals, email requests or deletes are queued to replay on reconnect. There is no push-notification permission or background sync.

## What is actually stored

The cache has six allowlisted **public** assets: `study/index.html`, `pwa/study.css`, `pwa/register.js`, `manifest.webmanifest`, `pwa/lh-192.png` and `pwa/lh-512.png`. The worker seeds them from the committed `pwa/public-pack.js`; it **never stores a network response**. No private HTML, token, API response, email, user ID, material metadata, R2 URL or PDF is copied to Cache Storage. It does not change how the existing Auth SDK manages its normal session. The reading guide has no analytics, drafts or reading-history database.

Scope is relative to the published `public/` root, not hard-coded to the domain root. The app works with `/index.html` and `/public/index.html`. `start_url` also provides the stable default manifest ID for that mount. A worker version clears only prior `legalhub:public-study:` caches for **its own mount**. No global cache deletion, auth bypass, forced client reload or account-dependent offline fallback. Normal HTTP errors on Home are not hidden as offline successes. Query-bearing requests, credential headers, partial/range requests, private routes, other origins and non-GET requests pass through without a worker cache or write queue. Bare Home is network-first with `no-store`; only network failure produces its public fallback. This policy does not control a device’s ordinary HTTP cache or independent downloads.

## Develop, review and publish

- Update the human-readable study page, stylesheet, registration script, manifest or the two PNGs. Regenerate **only** the public pack: `node tools/build-public-study.cjs`. `node tools/build-public-study.cjs --check` checks that source and generated bytes agree (including on CRLF checkouts). The build has a fixed allowlist, no recursive asset search, network, bundler or package dependency. Do not add private reading content to the list. Changing the public content changes the cache revision.
- Publish the complete `public/` directory. Serve `sw.js` and its local import as JavaScript and the manifest as `application/manifest+json` (or compatible JSON). Do not rewrite them to Home/login or use a long immutable cache for the worker/import/manifest. Service workers require HTTPS, except for trusted local development contexts such as localhost. A mobile phone reaching an insecure LAN address is not equivalent to localhost.
- In a disposable browser, visit the published candidate’s **public** study page and check the ready status, manifest, icon sizes and scoped cache. Enter airplane mode, relaunch and open a guide. Use fixtures for all private operations; never upload/delete a real file, change a real role/level, or send mail to test offline behavior. See `tests/pwa/browser-smoke.mjs` for the automated loopback test. Browser/OS install prompts vary; desktop Chromium coverage is not a claim of physical iOS testing.
- Updates activate normally after tabs using the previous worker close. A disconnected device can keep its old **public** edition until it reconnects. For rollback, restore the previously reviewed assets together. To retire an installed worker, the operator should deliberately serve a replacement at the **same worker URL and scope** that unregisters itself and deletes only its own prefixed study caches; removing the manifest or returning 404 is not a reliable uninstall. Do not clear all site data or sign out everybody as a deployment strategy.
